# Contributing to Research Operating System

Thank you for your interest in contributing! This project aims to help researchers use AI responsibly while maintaining academic integrity.

---

## How to Contribute

### Reporting Issues

- Use [GitHub Issues](../../issues) to report bugs, broken links, or unclear documentation.
- Include the file name and section where you found the issue.
- Describe what you expected vs. what you found.

### Suggesting Improvements

- Open an issue with the label `enhancement`.
- Describe the improvement and why it matters for research quality.
- If suggesting a new module, explain what research workflow it supports.

### Submitting Changes

1. Fork this repository.
2. Create a branch: `git checkout -b fix/your-change-description`.
3. Make your changes.
4. Ensure all internal links and references are valid.
5. Submit a Pull Request with a clear description of what changed and why.

---

## Guidelines

### Content Standards

- **Preserve evidence-based research practices.** Do not weaken integrity rules, verification requirements, or traceability standards.
- **Keep modules focused.** Each module has a specific purpose — do not merge unrelated concerns.
- **Use clear, direct language.** Avoid generic academic filler or vague statements.
- **Test all markdown links.** Broken references degrade the user experience.

### What We Accept

- Bug fixes (broken links, typos, formatting errors)
- Improved explanations and examples
- New prompt templates (in `prompts/`)
- New domain adaptations (in the domain adaptation module)
- Translations and localization improvements
- Workflow diagrams and visual aids

### What We Do Not Accept

- Changes that weaken research integrity rules
- Generic AI-generated content without evidence basis
- Modules that bypass verification or audit gates
- Content that promotes academic dishonesty
